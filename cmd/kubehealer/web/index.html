The problem

Kubernetes restarts destroy the evidence you need.

Every minute of downtime costs revenue and trust, and today's tooling leaves engineers reconstructing failures after the fact.

Ephemeral evidence

When a pod is OOMKilled or crash-loops, stack traces and stdout buffers vanish before an engineer can look.

Cascading bad releases

A broken rollout crash-loops across replica sets and hits customers before anyone runs rollout undo.

Restart storms

Naive auto-restart loops burn node resources and throttle the API server when the real fault is elsewhere.

How it works

Detect → Capture → Heal → Report

A closed control loop built on the Kubernetes watch API, with guardrails at every step.

Detect

Classifies CrashLoopBackOff, OOMKilled (exit 137) and probe failures from pod status and events.

Capture

Snapshots live and previous container logs plus node pressure before any action is taken.

Heal

Runs the matching playbook: graceful restart, deployment rollback, or circuit-breaker suppression.

Report

Emits an incident with root-cause analysis to Slack, webhooks, Prometheus and a REST audit API.

Pre-kill forensics

Every incident ships with the logs and diagnostics that would otherwise have been destroyed.

Safe auto-rollback

Detects crash-looping new releases and reverts to the last stable revision automatically.

Anti-flapping breaker

Stops restart storms over a sliding window and escalates to a human instead of making things worse.

Get started

Install in one command.

# Deploy to any Kubernetes cluster
helm install kubehealer ./deploy/helm/kubehealer \
  --namespace kube-system \
  --set config.clusterName="prod-us-east-1"
# Try it locally, no cluster needed
git clone https://github.com/olumideadekunle/kubehealer
cd kubehealer
go run ./cmd/kubehealer -mode=simulate
